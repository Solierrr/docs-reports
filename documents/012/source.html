O que a disciplina pede e o que o projeto entrega?

O que a disciplina pede

A disciplina pede uma API REST em Java com Spring MVC integrada a um banco SQL Postgres, com Spring Data JPA, CRUD, divisão em pacotes do padrão MVC, validação de entradas e tratamento centralizado de exceções. Os extras incluem documentação com Swagger, uso de procedures e functions do banco, autenticação e autorização com Spring Security e uma segunda API para um banco NoSQL.

O que foi entregue

O repositório api-core reúne a API REST principal, com Spring Boot, JPA e Postgres. Ela separa controller, service, repository, domain e dto, valida os corpos das requisições com Bean Validation e responde erros no formato Problem Details por um tratador central. O contrato OpenAPI é gerado e exportado, a segurança usa JWT e permissões por papel, e a procedure generate_subscription_charge é acionada pelo código Java. O repositório api-messenger traz uma segunda API Java, com MongoDB.

Como ler este documento

Cada requisito tem um identificador, o enunciado oficial, a descrição do que o projeto entrega e links para os arquivos ou pastas que o comprovam, com referências à branch principal ou a commits específicos no GitHub. Os identificadores que começam com M são os requisitos mínimos para a nota 7,0, e os que começam com E são os extras. A numeração segue a ordem do enunciado da disciplina. Quando o mesmo padrão aparece em mais de um repositório, o documento mostra um exemplo e cita os demais pelo nome.

Onde a arquitetura exige integração entre repositórios?

Cobrança com regra no banco

O ChargeController recebe a operação, o ChargeService coordena a regra e o SubscriptionRepository aciona a procedure no PostgreSQL. O teste de integração exercita chamadas repetidas e a validação no banco. Controlador · Serviço de cobrança · SQL da procedure

Identidade e permissões compartilhadas

O api-auth emite o JWT, e o api-core valida o token e aplica regras de autorização com Spring Security. O gateway Kong reúne as entradas dos serviços. Essa divisão permite evoluir a autenticação e os domínios de negócio em serviços próprios. Serviço de identidade · Configuração de segurança · Arquitetura do gateway

Mensagens com persistência e atualização em tempo real

O api-messenger combina endpoints REST para conversas e mensagens, persistência em MongoDB e comunicação por WebSocket com STOMP. A combinação de requisições HTTP e eventos permite consultar o histórico e acompanhar atualizações no mesmo fluxo. Controller de mensagens · Camada WebSocket

Contrato de API verificável

O OpenAPI exportado registra o contrato do api-core. A coleção Bruno permite exercitar requisições, e o workflow de OpenAPI valida o contrato no repositório. Contrato OpenAPI · Coleção Bruno · Validação em CI
