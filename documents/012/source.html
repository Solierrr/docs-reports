O que a disciplina pede e o que o projeto entrega?

O que a disciplina pede

A disciplina pede uma API REST em Java com Spring MVC integrada a um banco SQL Postgres, com Spring Data JPA, CRUD, divisão em pacotes do padrão MVC, validação de entradas e tratamento centralizado de exceções. Os extras incluem documentação com Swagger, uso de procedures e functions do banco, autenticação e autorização com Spring Security e uma segunda API para um banco NoSQL.

O que foi entregue

O repositório api-core reúne a API REST principal, com Spring Boot, JPA e Postgres. Ela separa controller, service, repository, domain e dto, valida os corpos das requisições com Bean Validation e responde erros no formato Problem Details por um tratador central. O contrato OpenAPI é gerado e exportado, a segurança usa JWT e permissões por papel, e a procedure generate_subscription_charge é acionada pelo código Java. O repositório api-messenger traz uma segunda API Java, com MongoDB.

Como ler este documento

Cada requisito tem um identificador, o enunciado oficial, a descrição do que o projeto entrega e links para os arquivos ou pastas que o comprovam, todos na branch main do GitHub. Os identificadores que começam com M são os requisitos mínimos para a nota 7,0, e os que começam com E são os extras. Os identificadores seguem o enunciado oficial da disciplina. Quando o mesmo padrão aparece em mais de um repositório, o documento mostra um exemplo e cita os demais pelo nome.

Entregas adicionais

O que o projeto reúne nesta disciplina?

O projeto separa os microsserviços por responsabilidade, com autenticação em api-auth, mensageria em api-messenger, notificações em api-notify, recomendação em api-recommendation, e-mails transacionais em api-email e integração com os serviços Google em api-google. Um gateway Kong, configurado em infra-gateway, serve de entrada para as APIs, e os serviços seguem os padrões comuns de erro, de contrato OpenAPI e de autenticação entre serviços definidos em docs-warehouse.
